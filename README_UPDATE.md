# Селин и Тори: «Живой ритм» + «Лавка странствий»
27.10.2026 — **добавочный патч, не полный архив бота**.

## Установка (Windows PowerShell)

1. Сделай резервную копию работающего проекта и базы. **Не удаляй** `data`, `.env`, `STORY.json` и т. п.
2. Распакуй этот ZIP **в отдельную папку** (не поверх бота).
3. Укажи свою папку проекта (в кавычках):

```powershell
py apply_patch.py --project "C:\path\to\selin-tori" --check
```

4. Если `--check` завершился без ошибок, установи:

```powershell
py apply_patch.py --project "C:\path\to\selin-tori"
```

5. Перезапусти бота / задеплой через обычный Git/Bothost. На старте `init_db()` зарегистрирует **новые таблицы**. Старые таблицы и данные не удаляются. Скрипт сохраняет копии заменяемых файлов в `.selin_patch_backups/living_world_...`.

Патч проверяет структуру проекта. Если структура не совпадает или у тебя есть более новые, несовместимые версии изменяемых файлов, скрипт завершится **без изменений**. Не подменяй старые файлы вручную; пришли вывод `--check` вместе с текущей версией исходников для адаптации.

## Лавка

- Команда `/shop` (или `/lavka`) и кнопка **«🏮 Лавка странствий»** внутри Гардероба.
- Шесть текстовых предметов. Если OpenAI доступен и есть бюджет фоновых запросов, ИИ генерирует новый ассортимент; при сбое используется резервный каталог без рисунков.
- Цены фиксирует Python по редкости, **20–240 игровых монет**. ИИ не может назначать цены или награды.
- Кнопка «Обновить» предлагает новую подборку: первое обновление за день бесплатно, последующие 5, 10, 15, 20, затем 25 монет.
- Покупка происходит только по явному нажатию. Двойная покупка не списывает монеты повторно. После смены витрины старые предложения нельзя купить.
- Для Селин/Тори покупка сразу трактуется как подарок; для убежища — как размещение, для отряда — как походная вещь.
- Инвентарь сохраняется в БД. Вещи можно открывать и **использовать в сцене**. Игровые реакции ИИ сохраняются, а предметы (до 12 последних) подмешиваются в контекст свободных разговоров Селин/Тори и инициативы.
- Нет картинок или настоящих денежных платежей; предметы не дают механических бонусов, которые могли бы поощрять отказ от еды или чрезмерные нагрузки.

## Живой ритм

- Селин различает «хочу»/«планирую»/«съела» в естественной переписке. Питание предлагается **предпросмотром и подтверждением**, желания не записываются как факт.
- Одно сообщение с несколькими продуктами может стать одной записью приёма пищи; два отдельных записи (например, лепёшка и кофе) можно объединить после вопроса бота. Старые логи не стираются.
- Интрадневные разборы еды группируются и откладываются, а не дублируются после каждого продукта. Вечерний отчёт остаётся.
- Селин учится времени завтраков (после нескольких совпадений), учитывает поездки, сладкие перекусы и режим активности «Спокойная / Обычная / Заботливая».
- Действующие временные ограничения тренировок из отдельного патча учитываются в контексте, если тот установлен.

## Что намеренно не делаем

- Не запускаем самостоятельные списания монет, «награды» из ИИ, автоматический приём пищи без подтверждения или создание изображений для всех покупок.
- Не считаем отсутствие записи доказательством, что человек пропустил еду.
- Не меняем основной канон автоматически: предмет предлагает сюжетную возможность, но не принуждает текущую сцену.

## Локальная проверка

В ZIP находятся офлайн-тесты `tests/test_shop.py`, `tests/test_rhythm.py`, `tests/test_intents.py`. Они используют SQLAlchemy и тестовые заглушки без сетевых OpenAI-запросов.

После развёртывания проверь вручную: `/shop` → купить → инвентарь → использовать → поговорить с Селин; `/shop` → обновить → проверить сохранённую вещь; в чате написать «Съела лепёшку и выпила кофе», сначала увидеть **предложение**, затем подтвердить.

Важно: здесь нет доступа к твоему работающему Bothost, API-ключам и реальной базе, поэтому живые Telegram/OpenAI сценарии нужно проверить после установки.
